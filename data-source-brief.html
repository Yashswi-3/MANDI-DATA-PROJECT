02 Justification note — why this data was chosen

For the dashboard header, verbatim:

"This project uses the Government of India's official Agmarknet price and arrival records, pulled directly from Agmarknet's own public API (the same one its website uses), as the authoritative source for all tracked crops across both mandis. Per project guidance, a private aggregator would be prioritised over government data where it is available, cleaner, and within 3% of the government figure — however, on direct testing, no private source met that bar: Agriwatch offers no free or public access, and CommodityOnline's free tier is itself a re-publication of the same Agmarknet feed rather than an independently collected dataset. Government data is therefore used as the sole source, with private reconciliation to be added only if a licensed private feed is secured."

We initially used a data.gov.in mirror of this same data, which was easier to query in bulk — but live testing showed it only retained about 10 months of history for these specific mandis, well short of the 3-year requirement. We traced the actual API Agmarknet's own website calls internally and switched to it directly: confirmed live to return real, correct data back to at least 15-Jan-2024, and the running pipeline has data as far back as 25-Sep-2023 — covering the full 36-month window.

Each record carries Arrivals (quantity, in Metric Tonnes) and Grade alongside Min/Max/Modal price — so quantity and grade-split requirements are satisfied from this one source.

04 How it's extracted (running now)

Google Apps Script, calling Agmarknet's own API in parallel batches, writing to Raw_Data on a self-rescheduling trigger.

1
Call Agmarknet's API directlyOne call per (crop, date) pair returns that day's prices for every market in India reporting that commodity — no API key required.
2
Filter to our two mandis in-memoryOnly rows where Market = "APMC Azadpur" or "Jaipur (F&V) APMC" are kept; the rest is discarded immediately, nothing extra stored.
3
Fetch in parallel batches, adaptively pacedBatches of up to 10 requests fire together via UrlFetchApp.fetchAll(). Batch size automatically shrinks on a real HTTP 429 (confirmed live) and grows back after clean runs — self-tuning against Agmarknet's own rate limit.
4
Resume automatically across runsA self-created trigger continues the sync past Apps Script's 6-minute execution limit until the full 5-crop × 36-month range is complete. A LockService guard prevents duplicate concurrent runs.
5
Log real gaps, don't fake themA date that fails even after retry is logged to Fetch_Gaps with a reason — visible and auditable, not silently dropped or backfilled with synthetic values.

05 Dashboard: Looker Studio setup

All unit conversion and seasonality logic is done as Looker Studio calculated fields — the Raw_Data sheet itself is never modified, so the live sync can keep writing to it without conflict.

1
Connect the sourceLooker Studio → Create → Report → Add Data → Google Sheets connector → this spreadsheet → Raw_Data tab.
2
Verify field typesConfirm Arrival_Date is typed as Date (not Text) — it's stored as ISO YYYY-MM-DD, which Looker Studio should auto-detect; check this before building charts. Confirm Min_Price, Max_Price, Modal_Price, Average_Price, Arrivals_MT are typed as Number/Metric, not Dimension.
3
Add a Unit Selector parameterResource → Manage parameters → new Parameter Unit_Selector, type Text, allowed values kg / quintal / ton, default quintal.
4
Add calculated fieldsPrice_Display = CASE WHEN Unit_Selector = "kg" THEN Average_Price/100 WHEN Unit_Selector = "ton" THEN Average_Price*10 ELSE Average_Price END. Also add Year = YEAR(Arrival_Date) for the seasonality chart below.
5
Add filter controlsDimension control on Crop_Label, another on Mandi_Label, and a Drop-down (Parameter) control bound to Unit_Selector so viewers can switch units live.
6
Build the seasonality overlay chartTime series chart, Dimension = Arrival_Date (Month-Day granularity), Breakdown dimension = Year, Metric = Price_Display. This overlays 2023/2024/2025/2026 as separate lines on one seasonal axis — the recurring price-loop view your sir asked for.
7
Build the grade/quantity viewBar chart, Dimension = Grade, Metrics = SUM(Arrivals_MT) and AVG(Average_Price), filtered by the Crop/Mandi controls — shows real grade labels (FAQ, Grade A, Medium, etc.), not a forced binary.
8
Paste the justification noteAdd a Text element at the top of the report with the verbatim note from §02.

06 Open items

watch Grade is not a clean A/B split

Live data shows ~8 grade labels per market (FAQ, Local, Medium, Grade A/B/C, Small, Large). The dashboard shows these as-is rather than forcing a binary — more honest to the source data.

watch Substituted crops have real gaps

Green Chilli and Tomato have confirmed real data at both mandis, but not every single day (normal — arrivals aren't daily). Visible in Fetch_Gaps, not hidden.

resolved Private source — confirmed unavailable, decision made

Agriwatch (paywalled), CommodityOnline free tier (mirrors Agmarknet, not independent), e-NAM (public dashboard returns zero rows), and Kisan Suvidha (not a price database) were all checked live. None qualify. No synthetic/simulated "private" data is used, since that would misrepresent the methodology.

08 Dashboard style guide (premium finish)

The default Looker Studio palette reads as a template. These values are colorblind-validated (not eyeballed) and applied once at the theme level, not per-chart — the fastest way to make the report look designed rather than default.

Backgrounds & text

Page bg · #0d0d0d Chart surface · #1a1a19 Primary text · #ffffff Secondary text · #c3c2b7 Muted / axis · #898781 Gridlines · #2c2c2a

Year series (seasonality overlay) — fixed order, not cycled

2023 · #3987e5 2024 · #d95926 2025 · #199e70 2026 · #c98500

Single accent for every other chart/scorecard (arrivals, grade, current price): #3987e5 — one accent used consistently reads as designed; a different color per chart reads as default template.

Beyond color

  • Tabular/monospaced number alignment on scorecards, consistent decimal places (2 for price, 0 for arrivals) — mismatched decimals across scorecards is the most common "unpolished" tell.
  • One typeface for the whole report — system sans throughout, no display font on titles. Premium dashboards are typographically restrained.
  • Chart borders off everywhere — separate cards with whitespace, not visible borders or shadows.
  • Direct labels instead of legend boxes wherever there are only 1–2 series (e.g. the price scorecard needs no legend at all).
